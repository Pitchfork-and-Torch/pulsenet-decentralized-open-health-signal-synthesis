Signal Standardization Schema + Quality Framework: A Prompt for Accpetency Criteria

Standardization schema + quality framework (SSQF) is a crucial aspect of signal production that ensures optimal quality and interoperability between devices. The goal of this prompt is to design a standardized and comprehensive schema that meets accpetency criteria such as open license header, sources/provenance sections, and a dual-use refuse note when relevant. This SSQF will be used for signal processing in wearable environments and environmental monitoring.

Artifact Footer (Required in every accepted deliverable):
1. Open license header matching the project
2. Sources / provenance section (or explicit "no external claims")
3. Dual-use refuse note where relevant
4. "Forged on GrokForge" citations when dismantling sealed ki ts
5. No secret, PII or private home paths

Structural elements:
1. Signal: An entity that captures physical or electronic signals of interest in a specific environment.
2. Protocol: A sequence of instructions or commands for signal processing.
3. Application: A set of protocols designed to capture signals with specified features and requirements.
4. Device: A dedicated hardware component designed to process and transmit signals according to the protocol used by the application.
5. Signal processing: The task of analyzing, filtering, or modifying signals captured in the environment.

Examples:
1. Signal: ECG readings taken from a patient's wrist using a smartwatch worn on a daily basis. Protocol: Wearable ECG protocol with specified features for analyzing ECG signals and transmitting them to a cloud-based platform for further processing. Application: An app designed to analyze the signals captured by the wearable and transmit them to an AI algorithm for further analysis. Device: A smartwatch with built-in sensors that accurately captures ECG signals from the wrist and transmits them to the cloud-based platform.
2. Signal: Temperature readings taken from a weather station in a remote area. Protocol: Wx protocol with specified features for analyzing temperature data and transmitting them to a cloud-based platform for further processing. Application: An app designed to analyze the temperature data captured by the weather station and transmit it to a remote monitoring system for further analysis. Device: A weather station equipped with sensors that accurately capture temperature readings from the environment and transmit them to the cloud-based platform.
3. Signal: Audio recordings made during a musical performance. Protocol: Midi protocol with specified features for capturing audio signals, processing them using specialized software, and transmitting them back to the performer. Application: A music production app designed to capture and process audio signals captured during live performances. Device: A portable device equipped with sensors that can capture audio signals and transmit them to a dedicated software application for further processing.

Interop notes:
1. Protocols: A protocol is an explicit set of instructions or commands to be followed by signal processing applications in order to achieve specific results. Interoperability means that the same protocols are used by multiple applications.
2. Standards: Standards refer to a group of agreed upon protocols for signal processing. Interop notes should mention which standards are used and how they are used.
3. Examples: Examples can be provided in each deliverable to demonstrate interop note compliance.
4. Additional information: Additional information on specific protocols, such as the purpose of the protocol or any necessary software or hardware components, should also be included in the artifact footer.
5. Detailed instructions: If there are specific instructions for interoperability with other protocols, detailed instructions should be provided in each deliverable. For example, if a certain protocol is used to extract audio data from a file, detailed instructions on how to extract that data through that protocol should be included in the artifact footer.
